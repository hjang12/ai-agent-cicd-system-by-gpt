## CI Gate Design
- The production Render setting `After CI Checks Pass` waits on checks for a commit. A post-deploy smoke that itself waits for the new deployment cannot be part of those blocking checks without a circular wait.
- Therefore `janggi-browser-acceptance.yml` runs local Chromium browser acceptance on PR and main-push events. The production live-browser smoke is now `workflow_dispatch` only and must run after deployment; it no longer blocks the deployment it is supposed to verify.
- Janggi Python and Time Dashboard validation also include `render.yaml` in their paths, so changing the shared deployment configuration runs both projects' validations before either service is allowed to deploy.
